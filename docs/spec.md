# 项目规格

## RepoMedic

### 输入

- 目标 Python 仓库路径
- Issue、Traceback 或失败测试上下文
- 可选的外部模型配置

### 输出

- 候选根因与文件级证据
- 工具调用轨迹
- Verifier 的确认状态、执行命令与失败原因

### 安全与正确性约束

- 工具调用限制在目标仓库范围内。
- 未执行验证命令的结论不得标记为确认。
- 复杂案例由 Coordinator 分配专业调查角色，并在共享状态中去重证据。

## RedisDoctor

### 输入

- Redis 问题
- 带来源 URL、模块与版本元数据的 Markdown 或 JSON 证据
- 可选的 OpenAI 兼容生成接口

### 输出

- 结构化路由结果：`intent`、`module`、`rewritten_query` 与检索模式
- 基于证据的回答和 `cited_source_ids`
- 证据不足、引用不合法或生成失败时的结构化拒答

### 约束

- 检索结果必须通过 Redis 版本兼容过滤。
- 引用只能指向本次检索出的证据。
- 当前正式链路使用自定义的版本感知检索、证据筛选与引用校验；真实 LightRAG 检索尚未接入正式实验。

## QLoRA 实验

- 基座模型：`Qwen/Qwen3-4B`
- 训练方式：4-bit QLoRA，LLaMA-Factory
- 训练目标：结构化路由、引用选择、证据约束回答与拒答行为
- 公共资产：最终配置、数据 schema、脱敏样例和汇总结果
- 私有资产：完整人工审核数据、远端运行环境、Adapter 权重与逐轮实验日志
